=====================================================
  ProactiveClaw — Manual Test Plan
=====================================================

This tests: long-term memory (Mem0), pre-exit flow,
conversation summary, bandit reward propagation, and
memory recall across sessions.

Watch Terminal 2 (slack_server.py) for log output
throughout. Key logs to look for are marked with [LOG].


=====================================================
  SESSION 1 — Build up memorable context
=====================================================

Send these messages to your bot on Slack DM, one at a time:

1.  "Hey, I'm working on a project called Neptune. It's a
     real-time data pipeline using Apache Kafka and ClickHouse."

    → Agent should respond normally.
    [LOG] You should see tool calls in terminal.

2.  "I have a meeting with Sarah next Thursday at 2pm to
     discuss the Neptune deployment timeline."

    → Agent may check your calendar. That's fine.

3.  "My main concern is that the Kafka consumer lag is too
     high — around 45 seconds. I need to get it under 10."

    → Agent should search for solutions or give advice.

4.  "Also, remind me — I prefer Python over Java for any
     new microservices. And I use vim keybindings everywhere."

    → This is a personal preference. Mem0 should extract
      and store this as a fact.

5.  "Can you search for best practices to reduce Kafka
     consumer lag?"

    → Agent should use tavily_search. Verify it works.


=====================================================
  NOW WAIT — Let the session time out
=====================================================

Do NOT send any messages for 5 minutes (AGENT_TIMEOUT=300).

Watch Terminal 2 for these logs in order:

  [LOG] "[timeout] Session idle for 300s — running pre-exit flow..."
  [LOG] Tool calls for calendar/gmail/notion checks (pre-exit)
  [LOG] Agent says goodbye in Slack
  [LOG] "[memory] Stored X dialogue turns in SimpleMem"   ← Mem0 storage
  [LOG] "[summary] Conversation summarized and session archived"
  [LOG] "[sleep] Agent is now sleeping"

If you see all of these, Session 1 is fully working.


=====================================================
  SESSION 2 — Test memory recall
=====================================================

Wait a few seconds after the agent sleeps, then send:

6.  "Hey, what were we talking about earlier?"

    → Agent should either use its conversation summary
      OR call query_long_term_memory to recall Neptune,
      Kafka, ClickHouse, Sarah meeting, etc.
    [LOG] Look for "[tool] query_long_term_memory" in terminal.

7.  "What's my preference for programming languages?"

    → Agent should recall "Python over Java".
    [LOG] Should trigger query_long_term_memory or
      retrieve_long_term_memory.

8.  "What was the Kafka consumer lag number I mentioned?"

    → Should recall "45 seconds, target under 10".

9.  "Who am I meeting next Thursday and what's it about?"

    → Should recall "Sarah, Neptune deployment timeline".
    → May also check calendar.

10. "I've decided to switch from ClickHouse to DuckDB
     for the Neptune project."

    → This tests memory UPDATE. Mem0 should eventually
      reconcile "Neptune uses ClickHouse" with the new
      "Neptune uses DuckDB" fact.


=====================================================
  NOW WAIT AGAIN — Second timeout
=====================================================

Wait 5 minutes. Watch for the same pre-exit logs.
This session's conversation should also get stored.


=====================================================
  SESSION 3 — Verify cumulative memory
=====================================================

11. "What database am I using for Neptune?"

    → Should say DuckDB (the updated fact), not ClickHouse.

12. "Give me a summary of everything you know about me
     and my projects."

    → Should recall: Neptune project, Kafka + DuckDB stack,
      Python preference, vim keybindings, meeting with Sarah.
    [LOG] Should trigger memory tools.


=====================================================
  WHAT TO CHECK — Pass/Fail Criteria
=====================================================

[PASS] Pre-exit flow triggers after 5 min idle
[PASS] Goodbye message appears in Slack DM
[PASS] "[memory] Stored X dialogue turns" appears in logs
[PASS] Session is archived (check sessions/ folder)
[PASS] Session 2 recalls facts from Session 1
[PASS] query_long_term_memory tool calls appear in logs
[PASS] Agent recalls specific details (45s lag, Sarah, Python)
[PASS] No crashes or tracebacks in terminal


=====================================================
  TROUBLESHOOTING
=====================================================

"[warning] Mem0 initialization failed"
  → pip install mem0ai
  → Check OPENAI_API_KEY is set in .env

"[warning] SimpleMem storage failed"
  → This is the old log message but it wraps Mem0 now.
     Check the error after it.

No memory tool calls in Session 2
  → The agent might be using the conversation summary
     instead of long-term memory. Try asking about
     something NOT in the summary to force a memory query.

Agent doesn't go to sleep
  → Check AGENT_TIMEOUT in .env (should be 300)
  → Make sure you're not sending any messages

Pre-exit runs but no memory storage log
  → Check that mem0_data/ directory was created
  → Run: python3 -c "from memory import _get_memory; print(_get_memory())"
